0.3.0-rc1 Release candidate

October 27, 2026 · Notes and downloads · Documentation

A web UI and an HTTP API, both off until the document turns them on. Also named users with password logins, API tokens with roles, and checks against pasting the wrong secret. Rule logging now works on a node, and the image ships the QEMU guest agent.

New

  • The web UI. Turn it on with sparewall set management.web=true, then open https://<node>/ and sign in as a named user. It shows status and health as they change, and the history to roll back from. Edit the configuration as a form built from the schema, with a search over every setting, review the node's own dry run, and apply with a window to confirm in. A zone policy matrix edits several pairs of zones in one change, and admins manage users and tokens. The UI offers only what the user's role allows, the node checks every call regardless, and nothing loads from outside the node.
  • An HTTP API. Every method open to tokens is POST /call/<interface>.<Method>, described by an OpenAPI 3.1 document at /openapi.json generated from the node's own interfaces. The coordinator keeps the HTTPS port and passes API and UI paths to sparewall-httpd, a sandboxed service with no authority of its own. If it fails, health is degraded, not failed, so it never moves the gateway addresses.
  • Roles and API tokens. Tokens carry a role: monitor, viewer, operator or admin. A revoked token stops working at once, even on open connections.
  • Named users. sparewall user add|passwd|role|list|remove. Users are cluster secrets, so both nodes of a pair have them. Logins open 12-hour sessions, and five failed logins in 15 minutes lock that user out for the rest of the 15 minutes.
  • Safer secrets. sparewall secret set asks twice, warns about stray whitespace, and reports the stored length. sparewall backup --check-password checks a backup password before the first backup needs it.
  • The QEMU guest agent, limited to an allow-list: a node under libvirt, Proxmox or another QEMU host reports its addresses and can freeze its file systems for snapshots.

Fixes

  • Rule logging: a rule with log: true no longer leaves the node failed, and logged packets reach the journal.
  • Files the installer left unlabelled under /sysroot are labelled early in boot.
  • RUSTSEC-2026-0385 (ctutils), which 0.2.0 was not exploitable through.

0.2.0 Latest release

October 21, 2026 · Notes and downloads · Documentation

The CLI on macOS, arm64 Linux and Homebrew, an operator-driven failback for HA pairs, admin password logins over SSH as an opt-in, and node names as hostnames.

New

  • sparewall failover moves the gateway addresses to the node with the higher VRRP priority, or to --to NODE, from either node. It's gated on the target being a healthy backup with the same configuration, and connection tracking carries over. Sites that want automatic failback can set cluster.vrrp.preempt_delay_s.
  • The CLI on macOS, arm64 Linux and Homebrew: brew install sparewall/tap/sparewall, with shell completions, kept in step with each release.
  • Admin password logins over SSH, only when the document sets management.ssh.password: true.
  • The node name is the hostname, in prompts, the journal and anything else that reports it.

Fixes

  • The ACME client's certificate checks take the fixes for RUSTSEC-2026-0382 and RUSTSEC-2026-0383.

0.1.3

October 19, 2026 · Notes and downloads

  • Start an upgrade from either node of a pair. On the backup, sparewall upgrade hands the request to the master, which runs the same rolling, health-gated upgrade.
  • Fixed: a node already tracking the reference it upgrades to, such as :stable, is now upgraded instead of reporting it already runs the newest image.

0.1.2

October 19, 2026 · Notes and downloads

  • Fixed upgrades: images are signed in the format bootc and podman check, and CI verifies every published image against the node's own signature policy.
  • Fixed SELinux denials for bootc and for bootupd reading /boot.
  • New: the login banner shows the node's health, and an optional admin console password is synced to both nodes of a pair.

0.1.1

October 19, 2026 · Notes and downloads

Fixes for problems found after 0.1.0.

  • Kea serves no HA and makes no offers until a pair is paired, and a pair paired by applying on each node gets a common base.
  • A port forward refuses traffic from zones it does not cover.
  • The CLI explains an unknown SSH host key, and notices and reconnects when a change cuts its session.
  • SELinux lets the coordinator seal secrets to the TPM.

0.1.0

October 18, 2026 · Notes and downloads

The first release: milestones 0 to 5 of the design. A standalone node or an active/standby pair, configured from one document with confirm and rollback, serving DHCP, DNS and time, with remote-access WireGuard, ACME certificates and rolling, signed upgrades.

  • An unattended installer ISO, raw and qcow2 disk images, and the CLI for x86_64 Linux.
  • SHA256SUMS signed with the project key, and SPDX SBOMs for the image and the CLI.
  • The coordinator runs in its own enforcing SELinux domain.
